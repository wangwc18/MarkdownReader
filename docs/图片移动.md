# 图片移动对齐进展

2026-10-24，通过computer-use选中既有自建本地SVG，格式→图像→移动图片到…可用。点击后出现保存文件对话框，默认名透明色块.svg，类型All Files，标题实际为复制并更新图片路径到…。保存位置为本机此前对话框目录，不凭此认定默认目录规则。证据typora-image-move-dialog-tree.txt。

本轮只观察并取消，没有提交移动。原SVG的SHA256保持CE24067E76F2CD4ADF3C6E436941B13A38681C7A58A53C78D9CD988142591713，文档无修改标记。曾尝试打开新的专用移动样本，授权提示出现；使用用户此前允许的不是现在正常关闭后，样本未打开，未更改激活机制。准备的独立副本保留在build/test-tools/native-move-source。

后端文件历史新增RemoveAfter状态，为后续源文件移除保留原字节快照。组合操作撤销改为逆序：移动组合可先恢复源文件，再移除目标。如果源目录不存在导致恢复失败，目标副本仍保留；源位置被外部创建文件或目标被外部修改时，预检拒绝撤销。

image_move_history_test.go两项隔离测试覆盖源移除/恢复/重做、外部源文件与目标修改保护，以及恢复失败时唯一磁盘副本保持。后端及scripts包测试、go vet通过，现有图片复制回归通过。

尚未接入MoveImage/MoveImages API和前端菜单，不将此基础状态算作可用移动功能，也未更新运行EXE或预览ZIP。仍需实现完整目标选择、覆盖、跨盘、共享引用、源变化并发保护、会话限制、失败回滚、文档和文件撤销绑定，以及原生实际移动/撤销比较与GUI验收。

## Windows源字节保护

RemoveAfter操作不再在核对后直接按路径移除。现在以GENERIC_READ与DELETE访问打开源文件，仅共享读取，保持句柄期间核对20MB以内的原字节快照，拒绝目录和重解析点；匹配后用同一句柄设置FileDispositionInfo，关闭句柄完成移除。共享与句柄语义依据Microsoft的[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)及[FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)文档。

image_snapshot_remove_windows_test.go验证：锁持有期间写入、重命名、按路径删除均失败；关闭锁后匹配快照可移除；源字节变化时文件保持，目录拒绝。后端及scripts包测试、go vet通过，包括前一轮移动文件历史测试和现有复制回归。

仍未提供用户可用移动入口。该保护不等于完整跨盘/网络盘/目录替换并发保证；后续移动协调器还需处理目标写入与源移除失败的补偿，以及UI文档版本变化。源码已更新，预览程序与ZIP未变。

## 单张本地移动协调器与菜单

后续工作区源码已接入MoveImage和格式→图像→移动图片到…。通过原生保存对话框选择目标，锁定并核对原始源图后写入目标，再按持有句柄移除源图。目标写入与源移除共用一个文件历史令牌；撤销先恢复源文件，再移除/恢复目标。与当前文件同一身份时不移除；已存在且字节相同的另一目标不重写，只记录源移除。

前端复用复制路径的文档版本保护，文档变化时撤销文件效果；成功后更新当前文档中相同地址的所有图片引用并绑定撤销。不同拼写、片段、相对路径别名指向同一源文件的情况仍待处理，不能宣称全部引用都安全更新。网络、data、blob移动入口当前禁用；批量移动尚未实现。

image_move_test.go验证新目标/覆盖的原文保持、文件移动、撤销恢复旧目标和重做；相同文件无文件效果，相同内容目标撤销保留原目标；对话框旧快照变化拒绝且不落盘；只读源移除失败时恢复此前目标字节且不保留半条历史。初次同文件测试发现锁定后再次普通读取失败，已改为先识别同一文件身份，测试重跑通过。

后端与scripts包测试、go vet、前端67项测试通过；最新前端资源和生产测试构建build/bin/MarkdownReader-image-move-test.exe已生成。当前固定MarkdownReader.exe和预览ZIP尚未替换；单张原生目录操作、实际移动、文档/文件历史往返和原生比较仍须GUI验收，不能把本阶段当作移动功能最终完成。

## 路径别名与查询片段

移动前对文档实际图片的不同地址调用真实ImageLocation解析，收集规范本地路径相同的引用；不解析网络、data和blob地址，其他不可用图片不阻止选中源图的移动。源图解析失败或解析后正文发生变化时，不进入文件移动对话框。移动结果应用到收集的别名，并保留每个原引用自己的原始查询和片段后缀。

新增image-move-references.js及两项测试，覆盖相对/file URI/大小写分隔符路径、不可用与远程排除、查询片段、Markdown/HTML/引用式图片及普通链接/代码保留；前端69项测试与生产构建通过。

工作区生产入口8项集成检查通过（image-move-alias-result.json）：实际ImageLocation解析相对、点路径、file URI和引用式地址指向同一本地源图，移动结果分别保留red、query+blue、HTML green片段和缩放，普通链接及代码不变，一次撤销恢复所有原文。该检查替换了MoveImage返回值，不实际移动文件，不能算别名场景的原生对话框或文件事务GUI通过。当前固定入口已包含实现，预览ZIP未更新。

仍需实际别名移动与原生比较、跨盘和GUI覆盖、批量移动。规范路径比较沿用Windows常规大小写/分隔符规则；特殊大小写敏感目录、硬链接及目录并发替换尚未验证。
