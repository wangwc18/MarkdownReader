# 源码模式菜单可用性（2026-10-23）

通过 computer-use 在原有未保存窗口之外新建独立 Typora 1.3.8 窗口，按用户既有授权点击“不是现在”，输入固定列表/任务样本。原窗口未保存、撤销或关闭。

源码模式样本为两行无序列表、两个任务项与普通段落。光标移到文首后实际按 Ctrl+Shift+]，稳定截图和可访问性正文均保留首行 `- 父项`，没有重复标记。打开段落菜单，所有条目均禁用；格式菜单同样全部禁用，原始结构分别见 typora-source-paragraph-disabled-tree.txt、typora-source-format-menu-tree.txt。

| 上下文 | 原生观察 | 产品当前行为与验证 |
| --- | --- | --- |
| 源码模式 → 段落 | 标题、表格、代码/公式块、引用、列表、缩进、上下段落、引用/脚注/目录/YAML全部禁用 | 对整组及后代标记aria-disabled，退出键盘焦点序列，阻止点击/Enter/快捷键命令 |
| 源码模式 → 格式 | 全部格式、超链接、链接操作、图像和清除样式禁用 | 同上；阻止格式快捷键打开弹窗或改写文本 |
| 手工源码编辑 | 可以直接输入Markdown | Tab缩进编辑仍可用，撤销保持原文；不把菜单禁用等同于禁止普通编辑 |
| 切回即时渲染 | 观察到段落/格式菜单恢复，其他上下文禁用另行比较 | 模式切换/菜单重建刷新状态；渲染列表Ctrl+]及撤销回归通过 |

source-menu-availability-smoke.js 23项实际桌面检查通过；列表菜单专项更新为6项。先前9项源码列表快捷键检查虽然验证了旧实现，但其预期与本次原生证据不符，已被本轮结论取代，不能继续计为对齐通过。既有测试直接调用内部命令接口不等于用户通过源码模式菜单执行命令，必须分别解释。
