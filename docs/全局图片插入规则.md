# 全局本地图片插入规则

图像偏好增加“插入图片时…”的无特殊操作、复制、上传三个选择，以及“对本地位置的图片应用上述规则”。复制仍使用现有图片目录；上传使用已配置的 Custom Command、PicGo-Core 或 PicGo app 服务，沿用已有超时、输出、错误与异步文档保护。

普通文档可在没有 YAML、关闭 YAML 自动上传时使用全局上传。本地插入和剪贴板均接入规则；关闭本地应用开关时，普通本地文件只引用原位置，剪贴板仍按原本的本地存储流程保存。文档 YAML 复制目录优先于全局动作；允许的文档 YAML upload 优先于全局动作；未允许的 YAML upload 回落全局。此优先级是当前实现，原生完整优先级尚未验收。

新配置使用 imageInsertAction 和 applyLocalImageRules。没有新字段的旧配置继续读取 copyImages，保留原目录且本地规则默认开启；设置新选择后同步旧复制布尔值。无效动作返回设置错误，不执行上传。

新固定工作区构建通过 15 项生产检查（global-upload-rendered-result.json）：通过真实偏好表单选全局上传并关闭 YAML 上传，在完全无 YAML 的文档里由 computer-use 实际复制 PNG 和 Ctrl+V；本地持久上传器返回 file URI，32×24 加载与像素正确，正文保持、精确撤销重做、源码/渲染往返、保存与全新读取、重开加载通过；关闭本地规则后剪贴板 API 返回 assets 本地地址，切换复制/无特殊操作同步旧布尔设置。没有云端上传，也没有替换后端 API。

这 15 项不代替本地插入文件框和所有上下文的全局规则 GUI 验证。网络图片应用规则、全局指定绝对目录、Typora 所有复制预设的布局、原生实际上传与完整优先级仍存在差异；预览 ZIP 尚未更新。之前 YAML 的 29 项结果针对前一构建，本轮后端回归通过，但未把旧构建全部 GUI 检查冒充新构建复测。
