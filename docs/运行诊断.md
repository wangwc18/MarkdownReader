# 本地运行诊断

工作区开发构建在 `data/diagnostics` 写入本次会话的生命周期 JSONL。它用于调查一次未复现的目录取消后进程退出。

- 记录启动、批量复制目录框打开/返回、窗口关闭请求及主程序返回。
- 只保存事件名、UTC 时间和布尔状态，不记录正文、图片数据、文档名称或选择路径。
- 每会话日志最多约 1MB，达到上限停止追加；日志不可写不影响编辑或关闭。
- 一个只有启动记录、没有退出记录的会话不能单凭日志认定崩溃；可能原因还包括外部终止等，必须结合进程状态和其他诊断。

固定样本日志见 `copy-all-cancel-lifecycle.jsonl`：取消目录没有触发关闭，随后窗口关闭按钮走正常退出路径。原异常仍未定位，当前开发构建尚未替换便携 ZIP。

## GUI 未处理错误的独立输出

工作区生产构建现在使用本机 Go 1.26.1 的 runtime/debug.SetCrashOutput，将未处理 panic 和运行时致命错误同时写入 `data/diagnostics/crash-会话标识.log`，不依赖 GUI 启动是否带标准错误句柄。运行时持有独立的文件句柄副本。配置失败只记录启用布尔状态，不阻止编辑器启动。

这类报告用于保存运行时错误消息和堆栈，可能包含本地路径；它不同于上面只含事件和布尔值的生命周期日志。报告保存在本机，不自动上传。正常退出时关闭记录，删除本会话仍为空的报告；已有同名报告不覆盖。

这不能保证捕获所有 Windows 原生异常、强制终止或外部关闭。如果进程消失而没有 Go 报告，仍须结合进程和其他诊断，不能据此认定某个组件有错。

- 确认旧自建测试窗口干净后正常关闭，再以普通GUI方式启动一个实例。生命周期记录确认 crash-output enabled=true。

## 启动执行环境对照（2026-10-24）

同一 MarkdownReader-svg-forms-test.exe 从受限工具命令启动，父命令等待 45 秒和 30 秒时均确认子进程未退出；父命令返回后，独立观察器发现进程结束。第二次预先持有句柄取得退出码 -1（launcher-held-handle-exit.json），生命周期仅 started/crash-output，空 Go 报告。

对照仅改变启动执行环境：沙箱外启动相同 EXE，仍不重定向 stdout/stderr。父命令立即返回后，独立观察 30 秒仍存活且 Responding=true，computer-use 窗口列表亦存在（launcher-control-start.json、launcher-control-result.json）。随后同一实例通过 5 项 SVG 编辑检查并显式正常关闭。

据此推断工具执行环境在命令结束时清理后台子进程，可以解释这两次启动消失；这不是应用代码修复，也不能证明此前目录操作期间所有退出均属同因。后续 GUI 验证应使用允许持续运行的启动环境，保留进程句柄和退出记录，避免把启动器退出造成的终止误记为应用崩溃。便携环境稳定性仍待独立验证。
