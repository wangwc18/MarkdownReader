# 自定义 Pandoc 导出

在“文件 > 导出 > 导出设置”中，点击“添加导出项”。填写名称、Pandoc 输出格式及文件扩展名，保存后从“文件 > 导出”菜单选择该项。

例如：名称“Markdown 不折行”，输出格式 `gfm`，扩展名 `md`，附加参数填一行 `--wrap=none`。也可以使用 `html5`/`html`、`docx`/`docx` 等格式组合。

每行是一个完整参数，参数中的空格原样传给 Pandoc，不需要为整行加 shell 引号。例如：

```
--metadata=title:导出 ${currentFileName}
--wrap=none
```

已支持 `${currentPath}`、`${currentFolder}`、`${currentFileName}`、`${currentFileFullName}`、`${outputFileName}`、`${outputFileFullName}` 和 `${today}`。参数中的相对资源和模板路径按已保存 Markdown 所在目录解析；未保存文档没有当前路径变量。导出使用当前编辑缓冲区，不要求先覆盖保存原文。

参数也支持 YAML 前言变量，例如 `${title}`、`${author}`、`${project.name}`。列表可以使用 `${people.0}` 取第一项，整张列表 `${people}` 会用逗号加空格连接。空值和空字符串展开为空，未知字段保留原占位符。内置路径/日期变量优先，不被同名 YAML 字段覆盖；替换只做一次，字段值中的 `${...}` 保持字面内容。

例如文档开头写入：

```yaml
---
title: 项目周报
project:
  name: MarkdownReader
people: [作者甲, 作者乙]
---
```

附加参数 `--metadata=title:${project.name} / ${title}` 会把输出标题设为“MarkdownReader / 项目周报”。YAML 解析错误、循环引用或把整个对象当作文字变量时，会报告错误并保留已有输出文件。列表连接、空值及未知字段规则仍需对照目标 Typora 版本确认。

使用“上移/下移”调整自定义项顺序，直接编辑名称即可重命名；“移除”后点击保存才生效。取消会放弃此面板的修改。自定义项支持使用上次设置导出，以及覆盖上次输出；若上次导出项被移除，会提示重新选择格式。

Pandoc 模式的输出路径由保存对话框控制，附加参数不能包含 `-o` 或 `--output`。转换先写入同目录临时文件，转换成功后原子替换目标；转换失败会显示 Pandoc 错误并保留原目标。程序使用随包 Pandoc，不需要另外安装。

## 自定义转换程序

把“转换方式”改为“自定义转换程序”，填写程序路径或 PATH 中的程序名称。程序路径中的空格不需要额外引号；相对程序路径从 MarkdownReader 目录解析，便于把转换器随便携目录一起放置。程序的工作目录为当前 Markdown 文件目录，未保存文档使用 MarkdownReader 目录。

参数仍是每行一个，直接作为独立参数传入，不自动经过 shell。需要 shell 管道时可以明确选择 `cmd.exe` 等解释器并配置它的参数；单字段命令行编辑与完整 Typora 配置仍待对齐。

当前编辑内容同时通过标准输入传入，并提供 `${inputPath}` 指向临时 Markdown 快照。`${currentPath}` 仍是原文件路径，不会为了导出覆盖保存原文件。

输出方式有三种：

- “程序写入文件”：把 `${outputPath}` 放入程序的输出参数。该变量指向本次暂存文件，成功后替换用户选择的最终文件；`${outputFileName}` 和 `${outputFileFullName}` 仍按最终文件计算。程序必须实际生成输出文件。
- “标准输出写入文件”：程序标准输出原样作为导出文件内容，标准错误仅作为诊断消息。
- “仅执行命令，不生成文件”：不弹出保存对话框，不需要扩展名，执行后可显示命令输出。输出路径和输出文件名变量均为空；当前缓冲区仍通过标准输入和 inputPath 快照提供。“使用上一次设置导出”和“导出并覆盖上一次文件”会再次执行该命令。

例如使用随包 Pandoc 转为纯文本：程序填写 `tools/pandoc.exe`，扩展名 `txt`，输出方式选标准输出，参数四行分别为 `-f`、`markdown`、`-t`、`plain`。

启用“成功后显示命令输出”可查看标准输出/标准错误；转换失败或超时会显示错误并保留旧输出。转换任务超时为 90 秒。文件方式中，程序自身产生的额外文件或外部动作由该程序决定；MarkdownReader 对选定输出文件使用暂存与替换。

“命令输出编码”只控制消息和错误的显示，不改变标准输出模式写入文件的原始字节。默认自动使用现有 Unicode/GB18030 识别；可手动选择 GBK、UTF-16、Big5 等文本编码。自动模式不代表能识别所有控制台代码页。无法按所选编码显示时会给出选择编码的提示，导出文件不会因此被转码。

当前是自定义导出的已实现部分。单字段命令行编辑、其他导出后处理，以及内置 Pandoc 项的排序/重命名/隐藏等完整 Typora 选项仍待实现与对比。outputPath 使用暂存路径、输出日志编码、进程后代超时处理等细节也待完整比较。不能把此阶段称为自定义导出完整对齐。Typora 官方配置参考：https://support.typora.io/Export/ 。

## 导出后打开目录

每个自定义导出项可以选择“使用全局设置”“打开输出目录”或“不打开目录”。逐项设置优先于全局选项；旧配置没有此字段时沿用全局行为。文件输出打开最终文件的父目录，文件夹输出打开所选目录本身。不生成文件的动作不打开目录，此时设置面板隐藏该选项。

只在成功导出并保存导出设置后打开目录；转换失败或取消不触发。若启动资源管理器失败，会提示输出已生成但目录无法打开。

## 文件夹输出

自定义转换程序的“输出方式”可选“程序写入文件夹”。此时无需扩展名，导出时打开原生目录选择器，可取消或选择已有文件夹。参数中的 `${outputPath}` 是独立的暂存目录，程序可在其中生成多个文件和子目录；成功后将这些内容合并至所选目录，同名普通文件替换，未输出的原有文件保留。

转换失败或暂存内容含链接时不提交输出。合并前检查目录类型及链接，提交时保留原文件备份；中途写入失败尝试回滚。若目标目录或已提交文件被其他程序改动，停止自动回滚并保留恢复目录及“恢复清单.json”，错误中给出路径；清单中的 file 和 backup 相对于输出目录。不要在程序仍运行时手动移动恢复文件。

多文件合并不是整个目录的一次原子操作。异常终止后的自动恢复、并发修改的全部组合和转换程序后代进程仍待进一步验收。完成提交后若恢复目录清理失败，会报告错误并保留已生成输出；不能将所有报错都理解为目标目录完全未改动。
