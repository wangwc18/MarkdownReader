# 自定义图片上传（工作区构建）

“偏好设置 → 图像 → 上传服务”现有“无”和“Custom Command”。配置命令后，可使用“格式 → 图像 → 上传图片”处理选中图片，或“上传所有本地图片”处理文档中的本地图片。“验证图片上传选项”使用两张程序自带测试图片，“查看上次上传输出”显示当前会话最近一次运行的输出。

## 当前协议

命令按 Windows 参数规则拆分为程序及参数，不隐式添加 shell。图片路径逐项追加；同一源文件的多个本地引用只传一次。支持 `${filename}`（含扩展名的当前文档文件名）及 `${filepath}`，未保存时均为空。变量在拆分参数后替换，中文空格路径仍为单个参数。程序在当前文档目录运行，未保存时在程序目录运行。

退出成功后，从标准输出末尾取与图片数相同的行，接受 http、https、file 图片地址。标准错误只用于输出诊断，不混入地址解析。失败、返回数量不足或地址无效时，不改写文档。命令超时为90秒，标准输出和标准错误分别限制为4MB。源图片读取沿用20MB上限，单批最多2000个引用。

图片位置按调用时的文档快照解析，避免运行期间切换 YAML 根目录导致取错源。后端返回地址映射及原始正文，前端再次核对文档与正文，变化时保留输出而不覆盖新编辑。单张只替换选中出现位置，批量保留普通链接、代码示例及 HTML 的其他属性。撤销/重做处理文档地址；不会尝试删除远程上传结果。

协议参考：[Typora 官方上传说明](https://support.typora.io/Upload-Image/)。本机 Typora 1.3.8 的服务列表和自定义命令字段已通过 computer-use 盘点；尚未在 Typora 中执行同一上传程序对照结果。

## 证据

- Go 测试：Windows 参数边界、含中文空格的变量、带 & 的路径、末尾地址协议、数量不足、错误协议、失败 stderr、同源引用去重、正文和源图片保持、两张验证样本及临时文件清理。
- image-upload-result.json：15项生产联调通过，覆盖配置保存、验证API、单张/批量引用替换、标题与HTML样式、远程引用与代码保留、文档撤销重做、失败保持、输出、源码模式可用性和磁盘往返。
- image-upload-render-result.json：3项本地 file URI 返回结果渲染通过，两张32像素图片和一张48像素图片均正确读取。
- image-upload-output-ui-tree.txt：通过 computer-use 检查实际设置窗口、滚动到上传选项，点击“查看上次上传输出”，显示本地失败样本输出；取消后保留原配置。
- 后端/脚本包测试、65项前端测试、go vet及生产构建通过。

生产联调使用自建 image-upload-fixture.exe，仅将输入路径转换为本地 file URI，或输出预定失败信息，没有向第三方发送图片。不能把离线协议通过当成某个云服务或所有上传工具已经兼容。
