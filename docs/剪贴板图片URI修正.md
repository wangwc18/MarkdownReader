# 剪贴板图片地址：特殊字符目录

2026-10-24 在工作区生产构建中，通过实际 Windows 剪贴板复制 PNG 并按 Ctrl+V，复现并修复了图片目录包含中文、空格、百分号、井号和括号时无法显示的问题。

样本目录是 `图片 空格%25#(一)`。后端已生成合法 URI，但前端把每个 `%` 再次替换为 `%25`，导致原本 `%E5` 变成 `%25E5`。图片存储成功，引用却无法解析到真实目录。失败实测记录见 clipboard-uri-before-fix.json。

前端现在通过现有 Markdown 链接写入函数保留后端 URI，避免二次转义。读入剪贴板文件后、调用存储接口前同步最新文档内容，并在异步步骤后核对文档、正文及选区仍一致。切换文档或更改光标会取消尚未开始的粘贴；存储后发生变化时继续使用已有提示，保留图片位置而不误插入引用。

## 当前验证

在同一修正生产构建中，分别在即时渲染和源码模式实际按 Ctrl+V，各 12 项检查通过，见 clipboard-uri-after-fix.json、clipboard-uri-source-result.json：

- 通过可见测试按钮将自建 PNG 写入真实 Windows 剪贴板，随后由 computer-use 执行 Ctrl+V；没有用合成 paste 事件替代系统粘贴。
- 地址只需一次 URI 解码就得到真实目录，ImageLocation 与媒体读取均正常。
- 32×24 图片尺寸及像素保持（每通道误差不超过 1），即时渲染显示成功。
- 文档单次撤销与重做、源码往返、保存后全新磁盘读取、关闭再打开后的图片显示均通过。

前端 65 项测试和生产构建通过。该修改只涉及前端粘贴链路；本轮未重新运行未改动的后端测试。

## 验收边界

这是 MarkdownReader 的已复现缺陷修正，不是 Typora 在所有路径形式下的逐项一致证明。完整系统剪贴板格式、HTML 富文本粘贴、网络图规则、文件操作撤销与跨重启恢复、全部图片格式仍待对照。普通 Windows 10/11 离线便携环境仍未验收。

只更新工作区构建和源码包。便携 ZIP 仍未替换，先前一次取消目录后未解释退出的诊断继续保留。
