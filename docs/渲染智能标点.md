# 渲染时智能标点的工作区实现

Markdown 偏好新增“渲染时转换智能标点”，默认关闭。开启后普通正文显示弯引号、撇号、短/长破折号和省略号；当前编辑块恢复原始字符，代码、公式、标记、链接及 HTML 等保护范围不转换。输入时智能引号/破折号在该模式下不再修改源码。现有本地依赖版本未变。

PunctuationView 在内存中保存 text 节点的原始内容与显示内容，不往 Markdown 或 DOM 属性写入隐藏源码。编辑输入、组合输入开始、命令与序列化前恢复原始文本，再按显示状态重新转换。显示字符长短改变时映射正反向选区；恢复 Chromium 选区后同时恢复原焦点，避免自动聚焦编辑区。HTML 生成路径也已调用显示转换；固定样本的复制及 HTML/PDF 导出补充验证见下文。

## 2026-10-24 验证

以实际 Typora 样本 examples/智能标点渲染对照.md 对照。前端 72 项测试、完整 Go/脚本测试、go vet 与生产构建通过。当前构建三份报告共 23 项固定桌面检查通过：

- smart-render-result.json 11 项：显示与原生固定样本一致，行内和围栏代码不变，不因显示产生 dirty，源码/渲染往返保持，computer-use 真实点击正文并输入 X 后没有将弯引号/破折号/省略号显示结果混入 Markdown，精确撤销重做，保存关闭后新的后端读取一致。
- smart-render-selection-result.json 10 项：前后方向分别选择原文 5 -- 7 --- 9；激活时选中原文，失焦时选区对应显示 5 – 7 — 9，方向保留，加粗使用正确的原始 Markdown 范围，撤销精确。该组通过真实生产 DOM 选区及前端命令执行，不是原生鼠标拖动/键盘选区验收。
- smart-render-disabled-result.json 2 项：通过应用 API 恢复初始关闭设置后，显示回到原始标点，没有待恢复替换节点或源文档修改。

首轮失败原因最终定位为 Vditor 编辑根节点本身是 pre，代码保护误排除了整篇正文；初步补异步刷新没有单独解决该问题。修正为保护真正代码 pre，同时保留异步渲染后的更新。随后选区检查发现 Chromium setBaseAndExtent 会自动聚焦 contenteditable，使失焦块又显示原文；补上焦点恢复后正反向检查通过。失败记录保留 smart-render-before-refresh-failure.json、smart-render-selection-before-focus-fix.json，未将其计为通过。

最终测试设置恢复为 smartRender=false、smartQuotes=false、smartDashes=false，文档已保存。正常关闭并由预持有句柄取得 exitCode=0（smart-render-focus-held-result.json）。前端提供只读 getEditorDiagnostics 以查看就绪/加载/组合状态及替换节点数量，不包含文档路径或正文。
