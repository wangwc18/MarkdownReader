# 文档级图片复制目录（开发构建）

入口为“格式 → 图像 → 当插入本地图片时 → 复制图片到文件夹…”。文档须先保存；选择目录后写入 YAML `typora-copy-images-to`，同盘目录相对于文档路径保存。此规则只属于该文档，不改变全局“插入时复制图片”偏好。修改可撤销、重做，随 Markdown 保存。

本地图片插入及剪贴板图片存储优先使用此目录。未设置时沿用全局规则。支持相对或绝对目录；相对目录基于文档所在目录，与 `typora-root-url` 的显示地址解析分别处理。目录不存在时按需创建，目录创建或图片写入失败会返回错误。

## 实测证据

2026-10-24 通过 computer-use 操作 Typora 1.3.8，补齐之前无法展开的子菜单：其中包含“复制图片到文件夹…”和“上传图片”。未保存文档点击复制目录会显示“Document must be saved first.”。将自建样本保存为 build/test-tools/typora-insert-rule.md 后，选择 insert-rule-images 文件夹并保存，磁盘出现：

```yaml
typora-copy-images-to: insert-rule-images
```

子菜单原始结构见 typora-image-insert-rules-tree.txt。此前样本窗口曾设置过图片根目录，保存后现有图片地址不用于证明全新文档的地址规则。

MarkdownReader 实际点击三级菜单及原生目录框，9 项联调通过，见 image-insert-rule-result.json：相对 YAML、正文精确保留、全局偏好保持、撤销重做、源码模式往返、保存及全新读取、重新打开后目录规则、剪贴板后端存储地址与字节一致。剪贴板检查直接调用应用后端，不据此声称本轮实际粘贴 UI 已测试。

Go 测试覆盖相对/上级/绝对目录、非法 YAML 值、已有元数据与混合换行正文保持、重复设置不产生重复键，以及全局复制关闭时本地插入仍使用文档规则。后端与脚本包测试、65 项前端测试、go vet 及生产构建通过。

### 实际本地插入及冲突保护

进一步通过 computer-use 点击 Typora 的“插入本地图片…”并选择 32×24 SVG，等待 Copying 消失后确认副本位于 insert-rule-images，标签为源文件名（不含扩展名）。源、副本均为 224 字节，SHA256 一致，见 typora-local-insert-rule-tree.txt、typora-local-insert-rule-files.json。该旧窗口最后显示 Windows 绝对路径，尚未核对其当前全局相对路径偏好，不能据此断言所有上下文都应生成该形式。

修正了 MarkdownReader 原先只尝试一次摘要后缀、可能覆盖第二个已有文件的问题。现在通过不覆盖的原子创建提交副本；已有相同字节文件可复用，已有不同内容、目录或符号链接占据候选名时继续另取名称。后端测试覆盖原名与摘要后缀均被不同内容占用、重复插入复用、源文件保持，以及 8 个并发请求得到同一完整副本。单张读取沿用 20MB 上限。

插入标签改用源文件名，文件选择前同步正文，并在异步返回后核对原文档、正文和光标。若已变化，保留文件结果但不会将引用插入另一文档。local-image-insert-result.json 的 9 项实际原生文件框联调通过：48×36 同名异图、已有 32×24 副本不变、源标签、准确字节、渲染尺寸、文档撤销重做、源码往返、保存及全新读取。local-image-insert-stale-result.json 的 5 项延迟 API 模拟通过，验证切换文档与返回 null 时不误改正文；这 5 项并非真实原生目录框取消测试。
