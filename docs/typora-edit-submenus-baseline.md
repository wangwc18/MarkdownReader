## 删除范围、换行符与拼写入口补充（2026-10-24）

通过 computer-use 展开菜单，未执行删除命令。删除范围包含：删除块 Alt+Ctrl+Shift+P；删除当前行或句 Alt+Ctrl+Shift+L；删除当前格式文本 Alt+Ctrl+Shift+E；删除当前词 Ctrl+Shift+D。截图初帧颜色较浅，稳定可访问性树未标 disabled，因此不凭首帧认定禁用条件。上下文边界仍需独立行为验证。证据 typora-delete-range-tree.txt。

换行符包含 Windows 换行符（CRLF）、Unix 换行符（LF）、保存时在文末添加空行；当前 CRLF 和文末空行勾选，未改动。证据 typora-eol-menu-tree.txt。

拼写检查包含文档语言选择面板与全局默认组合框，详见 typora-spell-baseline.md；当前产品布尔开关不能算完成语言功能对齐。

## 当前格式文本的实测边界

在示例文档中分别点击格式正文，再实际按 Ctrl+E。computer-use 返回选中文本：删除线为 `~~删除线~~`，高亮为 `==高亮==`，HTML 下划线为 `<u>下划线</u>`。即当前格式的标记也包含在选区中。操作未修改文档。

MarkdownReader 修复后在同一删除线样本实际按 Ctrl+E，同样返回 `~~删除线~~`，见 format-selection-cua-result.json。嵌套、重复扩选及其他语法的完整规则仍未验收。

## 当前行或句的实测边界（2026-10-16）
使用自建 `examples/行句选择验证.md`，在 Typora 正常编辑界面实际点击并按 Ctrl+L：
- 中文第二句：选中 `第二句包含 加粗文字！`，不包含相邻句，渲染选区隐藏加粗标记。
- 英文第二句：选中 `Second sentence has words! `，包含句末后的一个空格。
- 代码块第二行：选中 `code second line`。
- 切换源码模式后，中文第二句处 Ctrl+L 选中整条源码行（包含前后句及加粗标记）。末尾换行符是否纳入选区仍待进一步核对。
这些案例不证明全部句子分割规则；缩写、小数、代码/公式/链接内标点、引用与列表标记、重复扩选仍待对比。

## 保留单换行符（2026-10-16）
在行句选择验证.md 中，通过编辑 > 空格与换行实际关闭“保留单换行符”：同一段内的软换行不再强制换行，代码块两行仍保留，文档标题保持未修改。重新启用后软换行恢复，已恢复原设置。显示 <br/> 为独立选项，本轮未实测其开关行为。

## 显示 <br/>（2026-10-16）
在已正常打开的自建行句样本文末临时输入 `HTML第一行<br/>HTML第二行`。渲染模式启用“显示 <br/>”时，第一行末尾出现灰色 `<br/>` 标记；关闭时标记消失，两行仍保持分行。已恢复设置并清除临时输入，保存恢复后的自建样本。此设置控制编辑标记显示，不等于禁止 HTML 换行。未实测 Typora 全部导出格式与复杂 HTML 容器。
