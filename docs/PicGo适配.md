# PicGo 上传适配（工作区构建）

图像偏好设置新增 PicGo-Core (command line) 与 PicGo (app)，保留“无”和 Custom Command。PicGo 模式显示程序路径与选择按钮；自定义模式显示命令。验证按钮分别使用对应服务处理两张程序测试图片。

## 原生基线

2026-10-24 通过 computer-use 检查本机 Typora 1.3.8：Core 模式有“验证图片上传选项”“下载或更新”“打开配置文件”和说明链接；应用模式有“PicGo 路径”、选择、验证、下载及说明。原始记录为 typora-image-upload-picgo-core-tree.txt、typora-image-upload-picgo-app-tree.txt。本轮未点击下载、更新、打开配置或执行原生上传，服务选择随后恢复为原来的“无”。

## 当前实现

- Core：将所选程序与独立的 `upload` 参数组合，后面追加各图片路径；沿用自定义服务的输出地址与错误处理。带空格的程序路径按 Windows 参数规则处理。
- 应用：向 `http://127.0.0.1:36677/upload` 发送 JSON `list`；检查成功标志、返回数量、每个地址和4MB响应限制。图片地址不能包含换行。禁用代理和重定向跟随，避免本地请求被转发。
- 应用未启动且连接失败时，尝试启动设置中的程序并等候接口，最长等待15秒；接口已连接后的上传继续使用整体90秒期限。启动分支已实现，但本轮未用真实 PicGo 验证，不能计为该项验收通过。服务已经返回错误或请求已经开始后，不自动重试上传。
- 程序选择使用原生 exe 文件框，路径只在保存偏好后持久化。当前不自动下载或随包分发 PicGo-Core；这与 Typora 的内置 Core 分发仍有差异。

协议参考：[PicGo 应用高级使用](https://docs.picgo.app/gui/guide/advance)、[PicGo-Core 仓库](https://github.com/PicGo/PicGo-Core)。它们说明命令行和本地服务的公开接口，不能证明所有版本、插件与图床都已兼容。

## 本轮验证

Go 测试覆盖 JSON 路径列表、中文空格与 &、方法和请求头、返回地址、失败标志、缺少结果、错误协议、换行地址、无效 JSON、拒绝重定向及 Core 的独立参数。

picgo-upload-result.json 的14项生产联调通过：两个服务的偏好设置、两张验证样本、Markdown/HTML地址更新、HTML标题与缩放、输出、文档撤销重做。Core使用自建可执行协议测试程序；应用使用已确认属于本任务的本地测试服务，固定地址与产品一致。服务收到两次请求后，经专用停止入口正常退出，退出码0。两个替身仅返回 file URI，没有上传第三方。

后端/脚本包测试、65项前端测试、go vet 和生产构建通过。最后补充的地址换行保护再次通过后端测试；14项联调来自同轮之前的构建，未将它们描述为该保护的单独界面证明。
