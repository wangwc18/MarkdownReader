# 网络图片单张复制（工作区构建）

“格式 → 图像 → 复制图片到…”现支持 HTTP/HTTPS 下载源。先获取受限的图片字节快照，再打开原生保存框；确认后使用同一快照写入目标，避免保存期间重复下载。地址更新、目标冲突保护及文件/文档撤销重做沿用已有单张复制事务。

## 原生对照

2026-10-24 通过 computer-use 在 Typora 1.3.8 打开自建本地 HTTP 图片文档。两张图片引用同一 photo.png，选中第二张后执行复制：默认名为 photo.png，保存后的135字节副本与源 PNG 的 SHA256一致。切换源码确认只更新第二张，第一张 HTTP 引用和“保留标题”仍在。

原始证据：typora-http-copy-dialog-tree.txt、typora-http-copy-result-tree.txt、typora-http-copy-source-tree.txt、typora-http-copy-files.json。当前 Typora 关闭了相对路径偏好，因此生成 Windows 绝对地址；MarkdownReader 测试保留其相对路径偏好，生成相对地址。两种设置下的地址表现不作为完全一致的证明。

## 产品验证

MarkdownReader 实际点击第二张图片、菜单及原生保存框，同样默认 photo.png。http-image-copy-result.json 的9项通过：只改选中引用、相邻标题保持、源字节一致、文件效果令牌、撤销移除副本并恢复HTTP、重做重建、模式往返、保存后全新读取、重新打开后32像素图片渲染。

后端测试覆盖下载快照不重复请求、重定向、PNG字节、文件撤销重做、HTTP404、声明超限、空响应和非图片类型失败不生成目标。后端/脚本包测试、go vet与生产构建通过。前端未改动，本轮没有重复运行未改动的65项前端测试。

测试服务器只在回环地址提供自建 PNG，验证后通过专用停止入口结束，退出码0。未从外部站点下载测试图片。

## 限制与未完成

单张网络图片限20MB，下载90秒超时，最多10次重定向；支持当前 MIME 列表。认证/Cookie/Referer、代理环境、真实 HTTPS 证书和更多图片格式、取消下载、所有复杂 URL 与原生网络复制撤销尚待对照。

后续“复制所有图片到”已加入混合HTTP与本地文件实现，具体14项联调和未验收部分见批量网络图片复制.md，不能据单张支持推定批量原生对照完成。网络移动、完整下载全部功能与干净Windows10/11便携验证继续保持未完成。

当前只更新工作区构建和源码包，现有便携 ZIP 尚未替换。
