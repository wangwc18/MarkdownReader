# 新增图片地址的网络规则

图像偏好新增“对网络位置的图片应用上述规则”，默认关闭，与本地位置开关独立。通过“图片地址”对话框新增 HTTP/HTTPS 图片时，关闭规则或选择无特殊操作会保留原 URL；选择复制则下载到图片目录，选择上传则下载到专用临时目录后调用已配置服务，插入返回地址。编辑已有图片地址不自动重新处理。

复用现有下载器的 90 秒超时、20MB 限制、HTTP 状态、类型与重定向检查。复制沿用不覆盖不同字节的名称分配，保留 URL fragment，HTTP query 用于下载请求。上传沿用文档快照与输出保护；拒绝返回即将清理的临时文件地址。下载后再次检查文档内容和路径，变化时不调用上传器或写入文档图片目录。临时下载文件成功/失败均尝试清理。

前端提交前后核对原文档和正文，异步处理期间还核对插入点。首次真实提交发现对话框关闭后源码光标回到 0，导致新检查误拒绝正常插入；已在异步开始前恢复对话框打开时的插入点，继续检查后续变化。修复前失败记录为 network-image-insert-before-cursor-fix.json，修复后重新通过真实确认按钮复测。

## 2026-10-24 验证

后端测试覆盖关闭时没有 HTTP 请求、下载字节与编码片段、远程/本地开关独立、离线上传、404、不变正文、临时清理、下载期间正文变化时不生成目标文件。完整 Go/脚本测试、go vet、前端 69 项测试与生产构建通过。

network-image-insert-result.json 的 15 项生产检查通过：computer-use 实际确认新增图片地址对话框；复制得到期望的相对路径、片段、标题及精确 PNG 字节；关闭网络规则保持原 URL；离线上传得到持久 file URI，独立于已关闭的本地规则；精确文档撤销重做；404 保持原正文及之前重做分支；图片渲染 32×24；模式切换与保存关闭后的新后端磁盘读取一致。后续地址用实际前端对话框执行，没有替换 API。

第一次修复后验证器尝试从 WebView 跨源 fetch 原服务，因服务不提供 CORS 而失败；这不是下载接口失败。改用自建服务源码中的已知 PNG 字节与通过应用媒体接口读取的目标比较，没有更改应用或浏览器网络策略。原记录保留为 network-image-insert-verifier-cors-failure.json。

测试偏好通过应用 API 恢复，临时 image-network-insert-* 目录为 0；程序显式正常关闭且预持有句柄取得 exitCode=0（network-insert-fixed-held-result.json），HTTP 服务经其专用本机 shutdown 正常结束。
