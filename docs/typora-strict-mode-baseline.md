# Typora 1.3.8 严格模式实测

2026-10-20，通过 computer-use 读取本机偏好设置并打开 examples/严格模式验证.md。原设置是严格模式启用，临时关闭后重新打开相同文件观察不同结构，结束时恢复启用并截图确认。此前将受限进程列表的空结果作为完整退出证明，2026-10-23发现此依据可能漏报，因此撤回“全部进程退出/完整重启已验证”的断言；保留实际截图与结构观察，完整重启门槛需单独重测。

| 样本 | 严格模式启用 | 严格模式关闭时的观察样本 |
|---|---|---|
| `##标题缺少空格` | 普通文本，保留两个 # | 二级标题，隐藏标记 |
| `## 标题带空格` | 二级标题 | 二级标题 |
| `\##转义标题` | 普通文本，显示两个 # | 同左 |
| 行内代码中的 `##行内代码` | 代码字面文本 | 同左 |
| 引用内 `##引用内缺少空格` | 普通引用文本 | 引用内二级标题 |
| 引用内 `## 引用内带空格` | 引用内二级标题 | 同左 |
| 围栏代码内 `##围栏内缺少空格` | 代码字面文本 | 同左，语法高亮不算标题 |
| `1. 单位标记` 后两空格/三空格 `-` 项 | 退出有序列表，成为外层无序列表 | 成为有序列表第一项的子列表 |
| 后续 `10. 双位标记` | 单独有序列表，显示 10. | 同一有序列表第二项，显示 2. |
| 上述 `10.` 后两空格 `-`，再四空格 `-` | 第一层无序列表不在有序列表项内，四空格项是其子列表 | 两空格项位于有序列表第二项内，四空格项再嵌套一层 |
| 无序项后空行和两空格续段 | 续段在列表项内 | 同左 |
| 无序项后空行和一个空格续段 | 续段在列表外 | 同左 |

原始可访问性结构分别保存在 typora-strict-enabled-tree.txt 和 typora-strict-disabled-tree.txt。标题差异同时由实际截图确认，不能仅凭可访问性树缺少标题节点推断样式。文件只打开和观察，没有进行正文编辑或保存。

出现的 License Info 使用程序提供的“不是现在”正常关闭，未修改授权机制。此前对旧窗口记录及完整退出的推断不能仅凭受限进程列表成立；以后使用完整进程视图并结合窗口状态核验。原有空白测试窗口经确认没有正文后关闭。

这些是所列固定样本的基线，不涵盖全部 GFM、列表续段或复杂混合容器。MarkdownReader 随后加入对应选项，已通过所列样本的渲染、HTML 导出、编辑原文保持、撤销与保存往返检查，详见 strict-mode-research.md。不能将这些样本视为完整语法对齐通过。
