# Typora 渲染时智能标点实测

2026-10-24，通过 computer-use 在既有可用 Typora 1.3.8 窗口“另存为”创建 native-smart-render.md，原图片移动样本未覆盖。切换源码后写入并保存自建固定样本，内容另存 examples/智能标点渲染对照.md。

## 实际步骤与观察

初始智能标点菜单的截图显示：输入时转换勾选；渲染时转换、智能引号、智能破折号、Unicode 标点均未勾选。先选择渲染时转换，再启用智能引号，切换到渲染界面。

普通段落原文：

```text
"Hello", 'world'. It's 5 -- 7 --- 9...
```

实际渲染可访问性文本为：

```text
“Hello”, ‘world’. It’s 5 – 7 — 9…
```

同行内代码 `"code" -- --- ...`、text 代码块中的 `"fenced" -- --- ...` 保留原始标点。证据为 typora-smart-render-observed-tree.txt。切回源码后直引号、--、---、... 仍在，磁盘保存文件也是原始 Markdown，不是渲染结果。

随后关闭智能引号，渲染区仍显示转换结果；恢复输入时转换并做源码/渲染往返后也仍显示旧结果。因此这轮不能证明各开关在全新解析中的独立性或刷新时机，不能将“渲染结果仍在”解释成模式没有恢复。

最后重新展开菜单，截图确认输入时转换勾选，渲染时转换、智能引号、智能破折号、Unicode 标点均未勾选，与测试前一致；菜单已收起。独立样本文档保存，未修改其他原生窗口。磁盘样本和 examples 副本 SHA256 均为 3BFC232B99E681B80967174D7DC1F44F40728F1FB86840482686E08B04F540A6。

## 实现约束及未完成项

盘点时 MarkdownReader 仍缺少渲染时转换。这项不能通过替换 Markdown 原文实现：必须让显示转换与源文本分离，保证编辑、撤销、模式往返、复制及各格式导出符合原生行为。当前本地 Lute 资源检索只找到 SetFixTermTypo 一类词项修正接口，未找到可直接打开本次完整智能标点行为的导出设置。后续已独立实现显示层并通过固定样本的 23 项工作区检查，见 [渲染智能标点.md](渲染智能标点.md)，完整对齐仍未通过。

本轮没有修改程序或生成新 EXE。引号跨格式边界、嵌套、转义、链接/HTML/公式保护、缩写、数字、连续多引号及更多语言、渲染开关刷新、复制/导出和输入模式的全部行为未验收。完整智能标点仍不能标为完成。
