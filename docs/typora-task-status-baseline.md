# 任务状态菜单与作用范围（2026-10-23）

computer-use使用独立Typora 1.3.8未保存测试窗口，原公式样本窗口保持。先前样本的普通条目与任务条目处于同一Markdown列表：点击待办文字、Ctrl+L选中整项后，任务状态仍禁用。记录见typora-task-selected-mixed-menu-tree.txt。

将本轮自己创建的样本改为仅两项：`- [ ] 待办`、`- [x] 已办`。切回渲染并Ctrl+Home后，任务状态启用，子菜单实际为“切换任务状态”、分隔线、“标记为已完成”、“标记为未完成”。原始菜单见typora-task-status-menu-tree.txt。

| 操作与前置状态 | 原生实际结果 |
| --- | --- |
| 首项光标，无选区；未完成/已完成 | 切换后两项均完成，第二项不变，说明只作用当前项 |
| Ctrl+A选中两项均完成；标记为未完成 | 两项均未完成，选区保留 |
| 继续选中两项均未完成；标记为已完成 | 两项均完成，选区保留；源码树见typora-task-complete-source-tree.txt，两个标记均为[x] |
| 两项均完成且选中；切换任务状态 | 两项均变为未完成，选区保留，稳定截图确认 |

以上说明了先前无法启用的一项原因：混合列表与纯任务列表不同。不能据两个样本推断所有嵌套、不同列表符号、跨容器选区的完整规则。

## MarkdownReader实现与验证

- 同名子菜单包含三个真实命令，源码模式和普通/混合列表上下文禁用。Vditor会将混合原文拆成两个DOM列表，所以除DOM检查外，还检查原文相邻同层条目，避免误启用。
- 只替换选中行的任务前缀，正文中的[x]、[ ]、代码与链接保持；保留原有项目符号/缩进和字符数相同的光标/选区。重复显式标记不增加历史。
- task-status-smoke.js 24项实际桌面检查通过：纯/混合列表、三命令、当前项/多项、撤销重做、选区/光标保持、正文原样、重复标记、模式往返及源码禁用。新增5组单元测试用于文本保持与原文混合列表识别，不替代原生验收。
- 源码菜单23、列表菜单6、历史19、格式选区14项相关桌面回归通过；前端58项和生产构建通过。

复杂嵌套、引用内任务、不同列表符号、跨容器选区及与原生的全部启用条件仍待验证，本项仅基本固定样本通过。独立原生窗口现在保留两项均未完成的本轮样本，没有保存或覆盖原公式文档。
