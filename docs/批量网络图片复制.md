# 批量网络图片复制（工作区构建）

“复制所有图片到…”现在可以混合处理本地和 HTTP/HTTPS 图片，平铺生成副本并更新全部出现位置。相同 URL 的不同片段共享一次下载；查询参数参与资源身份，生成本地地址时移除查询参数而保留片段。不同资源同名时另取后缀，不覆盖已有文件。

所有资源读取、大小检查与目标规划完成后才写入文件。任一下载失败时，整个批次尚未落盘。沿用单批128MB和2000引用限制，网络单张20MB/90秒限制。整批副本与正文作为一次文档历史变化，撤销移除新副本，重做按快照恢复。内嵌 data URI 和 blob 仍保留原引用并报告未处理数量。

## 验证

- 后端测试覆盖：同URL片段去重且只请求一次、不同查询参数作为独立资源、网络查询不进入本地引用、三个引用产生两个副本、准确字节、整批撤销重做，以及第二个资源404时目标目录保持空。
- 原有本地复制冲突、外部修改保护、失败回滚等回归继续通过。旧测试中“HTTP被跳过”的断言改为仍未支持的data URI；未移除原来的本地文件保护断言。
- 可见诊断生产构建中通过computer-use完成原生目录选择，http-copy-all-result.json的14项通过：四个出现位置、两份网络资源加一份本地资源、同名避让、查询/片段、标题和HTML缩放、三份副本字节、单次文档/文件撤销重做、保存及四张图片重新渲染。
- Go后端/脚本包测试、65项前端测试、go vet和生产构建通过。

测试使用本任务自建回环图片服务器。测试服务器最后正常退出，诊断实例在保存并重新打开样本后正常退出，捕获退出码0。Typora单张网络复制已有实测，**本轮没有完成Typora批量HTTP、查询和片段的直接对照**，这些行为不能计为完整一致。

## 目录框退出诊断

首次通过通常的启动方式运行新构建，打开目录框后窗口消失；CIM仅剩旧测试进程，新调试端口不可用，生命周期止于copy-all-dialog-open。没有正常退出记录、Go堆栈或匹配的近期Application事件，原因仍未确定。

随后启动带stdout/stderr捕获的隐藏诊断实例，它持续存活但没有可操作的可见窗口，正常关闭返回0。再启动可见交互诊断实例，同一目录框完成选择，14项检查通过，最终正常退出0。stderr只有WebView2环境创建消息。完整生命周期见http-batch-visible-lifecycle.jsonl。

这些证据只证明带捕获的可见实例能够完成操作，不能证明此前的退出已经修复。旧测试窗口保留；未因一次观测失败重启它。便携ZIP继续保留旧阶段，当前仅更新源码包及工作区构建。
