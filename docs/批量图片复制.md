# 批量图片复制（开发中，尚未更新便携 ZIP）

当前工作区生产构建已加入“格式 → 图像 → 复制所有图片到…”。选择已有目录后，将本地图片及HTTP/HTTPS下载结果平铺复制进去，更新 Markdown/引用式/HTML 图片出现位置；共享源文件只复制一次，不同图片同名时追加数字后缀。中文文件名保留，空格、井号等路径字符继续转义。代码字面量、普通链接、原引用定义及 HTML 缩放属性保持。后续网络实现、14项联调与新增目录框退出诊断见批量网络图片复制.md。

同一批文件作为一个撤销事务：撤销恢复文档并移除新副本，重做重新生成副本。执行前检查所有文件的预期状态；中途写入失败尝试逆序回滚，若回滚本身失败会报告错误。源文件不删除、不改写。已有目标不覆盖，重名另存。

### 后续诊断进展

同一带 stdout/stderr 捕获的进程重复执行 Esc、取消按钮、再次 Esc，取消按钮和后一次 Esc 均通过正文/撤销快照/索引/文件效果/保存状态/修订号保持检查，进程持续存活。随后显式请求正常退出，诊断进程返回退出码 0，没有崩溃堆栈。

工作区加入有限的生命周期记录，写入程序旁 data/diagnostics/lifecycle-会话标识.jsonl，每会话文件限 1MB。只记录事件名、时间、选择是否成功/是否错误等布尔状态，不记录文档名称、路径、正文或图片字节；诊断写入失败不会阻止程序运行。前端诊断入口仅接受固定的关闭请求事件。

实际窗口验证见 copy-all-cancel-lifecycle.jsonl：Esc 取消产生 copy-all-dialog-open → copy-all-dialog-return（selected=false、error=false），没有关闭事件；随后实际点击窗口关闭按钮产生 before-close → frontend-close-request → request-close → before-close（allowed=true）→ runtime-return（error=false）→ main-return。新增诊断测试、后端/脚本包测试、go vet 和生产构建通过。

这些记录证明新构建能够区分取消与正常关闭，**并不证明此前一次未解释退出已经修复**。新诊断进程与旧进程均已正常结束；后续继续用此记录定位异常，同时推进剩余文档功能。
